# Audio integration (game side)

The pipeline generates **music + SFX** and bakes them into the exact shape the Stake Engine web-sdk
loads: **one Howler [audiosprite](https://github.com/tonistiigi/audiosprite)** played through the
`utils-sound` package. This matches how every example app (`apps/lines`, `cluster`, `ways`, …) ships
audio — verified against `StakeEngine/web-sdk`.

## What export writes

Into `dist/<game>/audio/` (deploys to `apps/<game>/static/assets/audio/`):

- **`sounds.ogg` · `sounds.m4a` · `sounds.mp3` · `sounds.ac3`** — every cue concatenated into ONE
  file, four encodings. Howler picks the first the browser supports. (`ogg` is emitted only when the
  build machine's ffmpeg has libvorbis — `m4a`+`mp3`+`ac3` already cover every browser; the Producer's
  Preflight flags this.)
- **`sounds.json`** — the audiosprite map (below).

Plus a single line appended to `assets.ts.snippet`, exactly as the example apps declare it:

```ts
sound: { type: 'audio', src: new URL('../../assets/audio/sounds.json', import.meta.url).href, preload: true },
```

pixi-svelte loads that into a `LoadedAudio { src, sprite }`, which `utils-sound` hands to
`new Howl({ src, sprite })`. All cues are loudness-normalized to **≈ −16 LUFS / ≤ −1 dBTP** before the
bake; looped cues carry the sprite loop flag so they repeat gaplessly.

## `sounds.json` (Howler audiosprite + volume map)

```json
{
  "src": ["./assets/audio/sounds.ogg", "./assets/audio/sounds.m4a", "./assets/audio/sounds.mp3", "./assets/audio/sounds.ac3"],
  "sprite": {
    "bgm_main":      [71000, 132452.83, true],
    "sfx_reel_stop_1": [325000, 243.6]
  },
  "config": {
    "bgm_main":      { "volume": 0.7 },
    "sfx_reel_stop_1": { "volume": 1 }
  }
}
```

- `src` — the four twins, relative to the served app root; Howler auto-selects per browser.
- `sprite` — `cueName: [startMs, durationMs]`, with a trailing `true` for looping cues.
- `config` — per-cue `{ volume }`, from each cue's gain in the pipeline.

Cue names follow the web-sdk convention the pipeline seeds by default: **`bgm_*`** looping music,
**`sfx_*`** effects (some looped, e.g. a reel-spin whir), **`jng_*`** jingles/stings.

## Wiring game events → cues (`utils-sound`)

Audio is played through `createSound`, which builds one `Howl` from the sprite and exposes three
players on separate volume buses — **`music`** (music bus), **`loop`** (looping SFX), **`once`**
(one-shot SFX). Declare the cue names as a union in `apps/<game>/src/game/sound.ts` (mirrors the
example apps):

```ts
import { createSound } from 'utils-sound';

export type MusicName = 'bgm_main' | 'bgm_freespin' | 'bgm_winlevel_big' | 'bgm_winlevel_mega';
export type SoundEffectName =
  | 'sfx_btn_spin' | 'sfx_btn_general'
  | 'sfx_reel_spin' | 'sfx_reel_stop_1'
  | 'sfx_anticipation' | 'sfx_win_tick'
  | 'sfx_winlevel_small' | 'sfx_winlevel_big' | 'sfx_winlevel_mega'
  | 'jng_bonus' | 'sfx_coin';
export type SoundName = MusicName | SoundEffectName;

export const sound = createSound<SoundName>();
```

The web-sdk's asset loader calls `sound.load(loadedAudio)` at boot (from the `sound` asset above).
Then trigger cues from your bookEvent / emitterEvent handlers — the `sprite` names ARE the cue names:

```ts
sound.players.music.play({ name: 'bgm_main' });            // base-game bed (loops)
sound.players.once.play({ name: 'sfx_btn_spin' });         // spin pressed
sound.players.loop.play({ name: 'sfx_reel_spin' });        // reel whir (loops)
sound.stop({ name: 'sfx_reel_spin' });                     // …stop on last reel
sound.players.once.play({ name: 'sfx_reel_stop_1' });      // reel lands
sound.players.once.play({ name: 'sfx_anticipation' });     // scatters teasing
sound.players.once.play({ name: 'sfx_winlevel_big' });     // win tier
```

`createSound` also gives you `stop` / `fade` / `rate` by cue name, and routes the music vs. SFX buses
to the player's `volumeMusic` / `volumeSoundEffect` settings automatically. Crossfading beds
(base ⇄ free-spins) is `sound.fade({ name, from, to, duration })` on the `music` player.

## Notes

- **Autoplay policy:** browsers block audio until a user gesture — start the bed on the first
  interaction (the web-sdk gates this on the AudioContext `running` state; see `createSound`).
- **`ogg` twin:** requires an ffmpeg built with libvorbis. Without it the sprite still ships
  (`m4a`+`mp3`+`ac3`) and every browser is covered — the missing twin is reported, never silent.
- **Licensing:** all audio is generated by gambling-safe providers (Stability Stable Audio / Google
  Lyria). ElevenLabs, MusicGen and Udio are excluded by policy/license.
